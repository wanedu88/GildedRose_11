# Gilded Rose Cursor Rules 작성 보고서

## 1. 작성 목적

본 보고서는 Gilded Rose C++17 프로젝트에서 Cursor AI가 일관된 기준으로 QA, 테스트 작성, 리팩토링을 수행하도록 프로젝트 루트에 `.cursorrules` 파일을 작성한 내용을 정리한다.

Gilded Rose는 레거시 코드 리팩토링 연습에 적합한 프로젝트이며, 기존 동작을 보존하면서 테스트를 강화하고 점진적으로 구조를 개선하는 접근이 중요하다. 따라서 Cursor AI가 임의로 도메인 규칙을 변경하거나 테스트 없이 리팩토링하지 않도록 명확한 작업 규칙을 정의했다.

## 2. 적용 기술 스택

`.cursorrules`에는 다음 기술 스택을 기준으로 작업하도록 명시했다.

- C++17
- CMake
- Google Test
- gcov/lcov

이를 통해 빌드, 테스트, 커버리지 측정 방식이 프로젝트의 기존 기술 스택과 일치하도록 했다.

## 3. 핵심 도메인 규칙

가장 중요한 절대 규칙은 `Item` 구조체를 수정하지 않는 것이다. Gilded Rose 카타의 핵심 제약 중 하나이므로, AI가 리팩토링 과정에서 구조체 필드나 public 형태를 변경하지 않도록 명시했다.

또한 품질과 판매 기한에 대한 도메인 불변식을 다음과 같이 정의했다.

- `quality`는 `Sulfuras`를 제외하고 항상 `0` 이상 `50` 이하를 유지해야 한다.
- `Sulfuras`는 품질이 변하지 않으며 `50`을 초과할 수 있다.
- `sellIn`은 음수가 될 수 있다.
- `sellIn`을 임의로 `0`에 고정하지 않는다.

이 규칙들은 기존 비즈니스 동작을 보존하면서 안전하게 코드를 개선하기 위한 기준이다.

## 4. 테스트 작성 규칙

테스트는 Given-When-Then 구조를 따르도록 작성 기준을 정의했다. 관련 동작은 `TEST_F` 기반의 fixture로 묶어 테스트 가독성과 유지보수성을 높이는 방향을 권장했다.

특히 다음 경계값을 반드시 고려하도록 했다.

- `quality == 0`
- `quality == 50`
- `sellIn == 0`
- `sellIn == -1`

Gilded Rose의 품질 변화 로직은 경계값에서 결함이 발생하기 쉬우므로, 해당 값들을 테스트 규칙에 포함해 회귀를 방지하도록 했다.

## 5. 리팩토링 규칙

리팩토링은 테스트가 Green인 상태에서만 진행하도록 명시했다. 이는 레거시 코드 리팩토링에서 가장 중요한 안전장치다.

또한 다음 원칙을 포함했다.

- 동작 변경과 리팩토링을 분리한다.
- 작은 단위로 점진적으로 리팩토링한다.
- 의미 있는 변경 후 관련 테스트를 실행한다.
- 매직 넘버는 가독성을 높일 수 있을 때 상수화한다.
- 불필요한 추상화나 복잡한 설계 패턴을 피한다.

이를 통해 AI가 과도한 구조 변경을 시도하지 않고, 테스트로 보호되는 범위 안에서 안정적으로 개선하도록 유도한다.

## 6. 기대 효과

이번 `.cursorrules` 작성으로 Cursor AI는 Gilded Rose 프로젝트에서 다음 기준을 지속적으로 따르게 된다.

- `Item` 구조체 수정 금지
- 품질과 판매 기한에 대한 도메인 불변식 준수
- 경계값 중심의 Google Test 작성
- 테스트 Green 상태 기반 리팩토링
- C++17, CMake, gcov/lcov 기반 작업 흐름 유지

결과적으로 레거시 코드의 기존 동작을 보존하면서 테스트 품질을 높이고, 안전한 리팩토링을 진행할 수 있는 기준이 마련되었다.
